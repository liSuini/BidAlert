# PRD: BidAlert 中标未签约项目进度追踪系统

## 1. 概述

中标未签约项目目前通过 Excel 清单手动管理，缺乏直观的进度可视化与自动预警机制。本系统提供一个本地部署的可视化大屏，让领导直观查看项目从中标到签约归档的全流程进展，自动计算各阶段预警/超期状态，并支持进展录入与 Excel 导入导出。

## 2. 目标

- 可视化大屏多视图展示项目进度（总览/看板/列表/管理）
- 按阶段时效规则自动计算项目状态（正常/预警/超期/已完成）
- 支持区分阶段超期与总时长超期
- 支持 Excel 导入项目数据 + 手动录入/编辑
- 支持按字段筛选导出 Excel
- 本地部署，数据不离开设备

## 3. 用户故事

### US-001: 项目数据存储与模型
**Description:** 作为系统，我需要持久化存储项目数据（23+ 字段），以便支持后续的查询、统计和展示。

**Acceptance Criteria:**
- [ ] 创建 Project 表，包含基本信息、时间节点、流程标记、进展记录字段
- [ ] 创建 StageConfig 表，存储阶段时效配置（5 个预设阶段）
- [ ] 创建 ImportLog 表，记录 Excel 导入历史
- [ ] 使用 SQLAlchemy ORM + SQLite
- [ ] 数据库初始化时自动插入预设阶段配置
- [ ] 投标主体为"信产"时，ict_digital_date 自动填充"不涉及"

### US-002: 预警计算引擎
**Description:** 作为系统，我需要根据阶段时效规则自动计算每个项目的状态，以便在大屏上直观展示预警和超期。

**Acceptance Criteria:**
- [ ] 实现工作日计算（排除周末）
- [ ] 按项目金额判定时限标准（500 万分界）
- [ ] 逐阶段检查：已用工作日 > 时限 → 阶段超期
- [ ] 逐阶段检查：已用工作日 ≥ 时限 × 80% → 预警
- [ ] 检查总时长：中标通知书获得至今 > 总时限(14/21) → 总时长超期
- [ ] 返回 status（normal/warning/overdue/completed）+ overdue_type（stage_overdue/total_overdue/both）+ overdue_stage
- [ ] ICT 立项结束字段根据投标主体动态选择（信产→ict_provincial_date，数智→ict_digital_date）

### US-003: Excel 导入功能

## 4. 功能需求

- FR-1: 系统必须支持 Excel 文件导入项目数据，自动映射字段并校验
- FR-2: 系统必须支持手动新增、编辑、删除项目
- FR-3: 系统必须根据阶段时效规则自动计算项目状态（正常/预警/超期/已完成）
- FR-4: 系统必须区分阶段超期与总时长超期，并标识具体超期阶段
- FR-5: 系统必须支持工作日计算（排除周末）
- FR-6: 系统必须提供总览、看板、列表、管理四种视图
- FR-7: 系统必须支持按字段勾选导出 Excel
- FR-8: 系统必须支持情况说明的手动录入与保存
- FR-9: 系统必须在阶段时间节点更新后自动重新计算状态
- FR-10: 系统必须本地部署，数据库使用 SQLite

## 5. 非目标（不包含）

- 不包含用户认证与权限管理（个人使用）
- 不包含主动推送通知（仅大屏视觉提醒）
- 不包含法定节假日自动识别（后续可通过配置表扩展）
- 不包含多用户协作功能
- 不包含对接外部招标平台 API
- 不包含移动端适配

## 6. 设计考量

- 大屏以深色主题为主，适合投影展示
- 视图切换通过顶部标签栏，切换不刷新页面
- 卡片和表格颜色编码：绿色=正常，黄色=预警，红色=超期，灰色=已完成
- ECharts 用于柱状图、环形图、地图等可视化
- Element Plus 提供表格、表单、弹窗等基础组件

## 7. 技术考量

- 后端：Python 3.11+ / FastAPI / SQLAlchemy / openpyxl
- 前端：Vue3 / Vite / ECharts / Element Plus / Pinia
- 数据库：SQLite（后续可迁移 PostgreSQL）
- 时区：Asia/Shanghai
- 日期精度：天（不记录时分秒）

## 8. 成功指标

- 大屏加载 200+ 项目时响应时间 < 2 秒
- Excel 导入 50+ 条数据 < 5 秒
- 领导可一眼识别预警/超期项目
- 项目状态更新后 1 秒内重新计算完成
