# ADR-0002: 项目状态实时计算而非持久化存储

## 状态
已接受

## 日期
2026-09-27

## 背景
项目的预警/超期状态需要根据阶段时效规则计算。可以选择：① 在数据库中存储状态字段，每次更新时重新计算并写入；② 不存储状态，每次查询时实时计算。

## 决策
不在数据库中持久化存储 status、days_in_stage、days_remaining 等计算字段，而是在 API 响应时由预警计算引擎实时计算。

## 理由
- **数据一致性**：状态是派生数据，存储会产生一致性问题（时间节点更新但状态未刷新）
- **计算成本低**：单项目状态计算为内存运算，200 条项目批量计算 < 100ms
- **逻辑集中**：所有计算逻辑集中在预警引擎，避免分散到多处维护
- **总时长检查依赖当前日期**：总时长超期需要与"今天"比较，存储的状态会过时

## 后果
- 优点：状态永远准确，无需维护状态刷新机制，代码简洁
- 缺点：每次列表查询需要计算所有项目状态（可通过缓存优化）
- 优化方向：后续可引入内存缓存，TTL 设为 1 分钟，数据更新时主动失效
